# Implementation reports

Implementation reports record **what was actually delivered and verified** for a phase or meaningful implementation slice.

They are evidence, not a second architecture document.

Use `../templates/implementation-report.md`.

Recommended naming:

```text
phase-0-implementation-report.md
phase-1-implementation-report.md
```

A report should include commit/range, changed components, plan deviations, verification actually run, externally/unverified acceptance areas, and follow-up risks.
