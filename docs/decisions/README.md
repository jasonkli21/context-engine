# Architecture decisions

Use ADRs for durable decisions that constrain future implementation and are not obvious from code alone.

Do not create an ADR for every small implementation choice.

Naming:

```text
0001-short-decision-name.md
0002-next-decision.md
```

Use `../templates/adr.md` as the template.

Status values:

- Proposed
- Accepted
- Superseded
- Rejected

If superseded, link both directions where practical. Do not delete old accepted ADRs; they are useful historical evidence.
